## 当前实现

App 唯一持有本地服务、权限、调度和效果执行。新增联动中心与日历页面，窗口关闭后菜单栏继续驻留；退出或睡眠不保证准点。只有取得 WorkbenchHost 单实例锁的 App 才初始化联动存储和调度。登录启动使用 SMAppService，由用户在权限页明确开启。

权限分为 macOS 系统权限、已选资源范围、Agent 连接授权、规则授权。Notes 启动后校验原账户和文件夹 ID，提醒事项复用原列表 ID，失效不创建替代资源。静默恢复可对已配置 Notes/已启用邮件规则做一次隐藏、不激活的应用启动，随后调用不弹窗的 AppleEvents 权限预检。后台与外部 Agent 在脚本入口再次检查，不能申请系统权限。没有模拟“已授权”；无法检查显示“待核对”。

每条规则冻结来源、分析 Agent、允许动作及具体输出资源。新规则默认不存在；保存模板是明确启用动作，旧 Agent 连接不会增加授权。换邮箱、撤权或范围失效时停止相关规则，显示修复入口。修改表单不改变旧规则；先停用旧规则，再重新保存范围。不得接管同名 Notes 文件夹/提醒列表/日历。

## 工作流

- 早间天气：13 个城市可选，包含巴黎。保存 WeatherCity 城市、坐标及时区；06:00 按 Mac 当前时区执行，08:00 前补跑并记录延迟，之后记录错过。当天一次。AI 分析失败仍展示实际预报，通知明确标注 AI 分析未完成，分析输入加密保留有限重试。
- 邮件助理：启用时建立游标，只处理此后邮件。每五分钟在所选邮箱内按日期谓词增量读取，120 秒重叠检查与去重；游标在持久接纳候选后推进。固定窗口按原生 ID 每页最多 10 候选，窗口完成才推进水位；重叠 ID 最多 20000，超量保留游标并报未完成，不丢弃去重记录。总邮箱数量不受旧搜索 1000 封上限影响；旧手动搜索上限保持兼容。超长/已删除/无法核实正文的邮件以元数据进入待看，不能推断正文或自动创建事项。
- 明确广告仅抑制工作台通知，记录分类；不删除、归档或标记已读。禁止广告分类附带写动作。重要邮件通知重点；不确定建议进入待确认。系统 Mail 自带通知由用户检查，不擅改系统设置。
- 需回复时创建并回读原生草稿。发件地址来自已选账户，收件地址从实际来源解析，不采用模型给出的地址。草稿写入绑定原邮箱 TaskLocal 范围。随后仍通过 Mail 页展示完整内容并逐封确认；任何 Agent 工具或自动化规则都没有实际发送入口。
- 日历和提醒：只管理专用资源。自动事项需要原文包含可核对的事项标题、明确 YYYY-MM-DD、HH:mm 和 IANA 时区；日历同时要求明确结束时间，不擅自推断一小时时长。其他表达保守进入待确认，可补充时间/时区；专用日历内冲突也先确认。不会邀请参会人。仅检查已授权专用日历，不声称核对了其他个人日历的冲突。
- 每日备忘录：一天一个归属 ID，每个来源/动作一个去重标记，汇总天气及邮件建议，保留内部来源标识。用户修改过的笔记不覆盖/不自动追加。Notes 100 条一页、最多 4096 条，归属账本扩容到同一有界上限。

## 引擎与分析 Agent

AutomationRule/Run/AgentDecision/EffectRecord 分别保存冻结授权、实际运行、结构化建议元数据和效果结果。请求去重使用规则/来源/动作的稳定哈希。执行前持久保留效果；未知结果不重放。多个动作分别记录，部分失败后不重复已完成部分；未执行建议加密排队，重启可继续。全局暂停、规则停用和连接撤权在准入时复查。已被接纳的系统动作不会伪称可撤回。

Codex 默认以 `exec --ephemeral --ignore-user-config --ignore-rules --sandbox read-only --output-schema` 执行，独立临时目录，禁用 shell/app/web tools，复用本机已登录身份。源邮件是数据，不能改规则或调用工具。临时输入输出不写普通日志，结束删除；待确认、分析重试和部分执行队列用 Keychain 密钥 AES-GCM 加密，七天到期清理。分析失败有五分钟间隔；不把格式错误、额度不足或超时转换成成功。

其他本地 Agent 可单独获 `automation.worker`，在模板选择该连接后领取专属任务。`automation.claim/submit` 为版本 1，任务绑定认证连接、随机租约、规则及到期时间，默认 60 秒；App 再次验证提案和授权。过期、重复或撤权提交拒绝。外部执行前再次核对连接授权；不允许自行开启规则、解除暂停或申请系统权限。

MCP 增加 `workbench_automation_status/runs`（独立 automation.read，仅脱敏元数据）、`workbench_automation_claim/submit` 和 `workbench_calendar_list/create/update/cancel`。日历读取/写入分别授权，授权绑定专用日历 ID；旧连接默认关闭。旧 CLI 与协议 1.0–1.6 继续兼容，本轮新操作只增加在版本化 Workbench wire v1，不谎称旧 CLI 已开放日历。

原生日历无事务性条件更新；修改前版本比较覆盖标题、时间、来源、位置、提醒、参会人和重复规则等。多应用同时编辑仍有最终核对与系统保存之间的竞态，实机验收需覆盖。
