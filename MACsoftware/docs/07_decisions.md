# Hushlight Mac 决策记录

> 更新日期：2026-08-13
> 规则：Accepted 决策是实现基线；变更必须新增替代决策并同步 PRD、架构和验收。

## 1. 已接受决策

### D-MAC-001 采用原生 SwiftUI 主线

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | macOS Bridge 使用 Swift 6、SwiftUI 和原生系统框架；最低系统为 macOS 13 |
| 原因 | 菜单栏、登录项、Keychain、权限、签名和系统自动化需要深度 macOS 集成 |
| 影响 | Windows 可独立选型，但两端共享工具、权限、确认、错误和结果契约 |

### D-MAC-002 M0 使用 SwiftPM 骨架，S1 转正式 App target

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted，细化于 D-MAC-004 |
| 日期 | 2026-08-13 |
| 决策 | M0 以 SwiftPM executable 建立骨架；S1-W1 建立 Xcode `.app` target 和 Development signing |
| 原因 | 系统权限和稳定应用身份需要 App bundle，但开发签名不等于正式产品交付 |
| 影响 | 正式 Developer ID、DMG 和公证仍在阶段三 |

### D-MAC-003 未集成能力显示真实空状态

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | 未配置服务、未申请权限和无动作记录按真实状态展示，不内置伪成功数据 |
| 原因 | 失败、离线和权限不足必须如实反馈 |
| 影响 | Preview/测试数据与生产实现隔离并显式标注 |

### D-MAC-004 采用三阶段 Mac 主线

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted，替代原 M1–M5 简化路线 |
| 日期 | 2026-08-13 |
| 决策 | 阶段一用 9–11 周完成局域网全部本地能力；阶段二用 5–7 周接云端并冻结上市功能；阶段三用 4–5 周完成正式产品准备 |
| 原因 | 先隔离验证本地执行难点，再引入云端依赖，最后集中处理发布身份和升级风险 |
| 影响 | 阶段一/二属于 V0 软件验证；阶段三形成 Alpha 可交付基线；排期按 1 名 Mac 开发者估算 |

### D-MAC-005 Mac 保持纯 Bridge

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | Mac 只负责连接、权限、动作、真实结果、诊断和更新；不承载聊天、角色、记忆、订阅、ASR、TTS 或设备运动 |
| 原因 | 设备是交互入口，Web 是配置大本营，Bridge 是本地执行器 |
| 影响 | 菜单栏常驻，管理窗口承载配置；Dock 默认隐藏并提供重启生效的用户开关 |

### D-MAC-006 Debug 测试台必须复用生产执行链

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | Debug 测试台和真实设备使用相同 `bridge-v1`、Decoder、Router、Policy 和 Adapter；Release 完全移除测试台 |
| 原因 | 防止测试路径通过而真实设备路径未验证，也防止调试能力进入产品 |
| 影响 | 测试台不能直接调用适配器或写入模拟成功 |

### D-MAC-007 先私有执行协议，后增 MCP 网关

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | V1 使用版本化私有 `bridge-v1` JSON Schema；后续可并行增加 MCP 网关，但必须转换为相同协议并经过相同策略 |
| 原因 | 需要先冻结跨平台动作、风险、确认、幂等和结果语义，不能让模型协议拥有本地权限 |
| 影响 | macOS、Windows、设备和云端共享 Schema；MCP 不直接访问适配器 |

### D-MAC-008 阶段一 LAN、阶段二 Cloud

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | 阶段一通过 Network.framework、Bonjour `_hushlight-bridge._tcp`、WSS 和配对密钥连接；阶段二增加出站云端 WSS，并以云端作为上市主通道 |
| 原因 | 固定研发局域网先保证设备联调，云端主通道再解决账户、跨网络和统一策略 |
| 影响 | LAN 和 Cloud 共用执行核心；Bridge 不开放公网入站端口 |

### D-MAC-009 首发能力与安全边界

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | 首发包含音量、Bridge 计时器、EventKit 提醒事项、白名单打开、媒体控制、网易云和微信草稿/确认发送 |
| 原因 | 覆盖环境调节、轻提醒、内容和高价值应用动作 |
| 影响 | 禁止 Shell、任意文件/URL、坐标盲点点击和未确认发送；微信阶段一只用测试账号/联系人 |

### D-MAC-010 固定应用身份和官网分发

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | Bundle ID 为 `com.hushlight.bridge.mac`；正式版本由官网下载 Developer ID 签名并公证的 DMG，不走 Mac App Store |
| 原因 | 稳定身份有利于 TCC 和 Keychain；官网分发更适合辅助功能和应用自动化 |
| 影响 | 阶段三启用 Hardened Runtime、secure timestamp、`notarytool` 和 stapling；不依赖 App Sandbox |

### D-MAC-011 自动更新采用 Sparkle 2.9.4

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted with prerequisite |
| 日期 | 2026-08-13 |
| 决策 | 阶段三精确固定 Sparkle `2.9.4`，使用 EdDSA appcast、灰度渠道和上一版本回滚 |
| 前置 | 引入前完成许可证、安全、依赖来源和完整性评审，并登记到项目依赖清单 |
| 影响 | 未完成前置时不得安装依赖或宣称自动更新完成 |

### D-MAC-012 数据最小化和无特权 Helper

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | 密钥/令牌存 Keychain；动作元数据最多 500 条或 7 天；诊断最多 20 MB 或 7 天；不增加特权 Helper |
| 原因 | Bridge 不需要管理员权限，且消息和本地上下文应最小保留 |
| 影响 | 自启使用 `SMAppService`；日志不得含联系人、消息正文、令牌或敏感路径 |
