## 2. 实现规则

1. 修改前先检查工作树，不覆盖用户已有改动。
2. 先更新需求、架构或决策，再实现会改变产品行为的内容。
3. UI 只呈现服务层返回的真实状态；演示数据必须显式标注且不能进入生产路径。
4. 每个适配器独立隔离，禁止把应用特有自动化泄漏到通用领域模型。
5. 所有动作返回成功、失败、拒绝或未知；禁止仅以“已发起”当作成功。
6. L3 动作必须具备确认令牌、幂等键和审计事件，且不得自动重试。
7. 不硬编码密钥、账号、联系人、生产地址或隐私数据。

## 3. 完成定义

- 代码可编译，相关自动测试通过。
- 手工验收项有可复查证据。
- 文档、进度和决策同步更新。
- 汇报已验证、未验证和剩余风险，不把开发测试写成用户验收。
