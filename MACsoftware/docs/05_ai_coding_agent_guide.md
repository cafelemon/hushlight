## 2. 每个子任务的完成定义

每个子任务必须同时完成：

1. 对应需求 ID、协议/适配器规格和验收 ID 已确定。
2. 实现只触及该子任务的模块和必要接口。
3. 自动测试覆盖正常、拒绝、超时、重复和权限缺失。
4. 实机测试记录应用、macOS、设备和协议版本。
5. 验收证据可复查，失败项没有被勾选。
6. `06_progress.md` 记录已验证、未验证、风险和下一步。

未完成测试和验收的代码不得进入阶段集成候选。

## 3. 实现边界

- App Shell 不直接调用系统或第三方应用；所有动作进入 `CommandRouter`。
- LAN、Cloud 和 Debug 测试台实现同一 `BridgeTransport` 输入语义。
- `PolicyEngine` 在执行前校验暂停、权限、风险、确认、版本和白名单。
- 每个适配器只实现一个能力域；应用特有元素和错误不能泄漏为公共协议语义。
- Release 构建不包含测试台、开发凭据、模拟成功或隐藏工具入口。
- 禁止任意 Shell、任意文件、任意 URL、坐标盲点点击、未确认发送和静默扩大权限。
- 不硬编码账户、联系人、生产地址、证书、令牌、配对密钥或消息正文。

## 4. 结果、日志和证据

- `ack` 仅表示收到请求，不能显示或播报为成功。
- 最终结果只使用 `succeeded / failed / rejected / unknown`。
- 相同 `request_id` 返回已有结果，不能重复产生副作用。
- L3 不自动重试；确认变化或失效后必须重新走用户确认。
- 日志使用稳定错误码，不记录联系人、消息正文、令牌或敏感路径。
- 演示、开发测试、实机集成、用户验收和生产验收必须分开表述。

## 5. 适配器变更流程

1. 记录目标应用 Bundle ID、版本、macOS 版本和接入方式。
2. 优先正式接口；使用 AXUIElement 前证明没有满足需求的稳定正式接口。
3. 只使用稳定元素语义，先做只读探测，再实现动作。
4. 定义执行前条件、成功证据、失败、未知和停用条件。
5. 在测试账号/数据上通过版本矩阵和故障注入。
6. 应用更新后先回归；未通过前远程停用适配器。

## 6. 协议和兼容规则

- `bridge-v1` 是 macOS、Windows、设备和云端的共享事实源。
- V1 新增可选字段必须保持旧消费者可忽略；删除、改义、收紧必填或改变枚举需要新协议版本。
- MCP 只能作为外层网关，将请求转换为 `bridge-v1`；不能直接访问适配器。
- Schema、Swift 类型、设备类型和跨平台契约测试必须在同一变更中更新。

## 7. Git 和交付

- 修改前检查 branch、status 和相关 diff，保留用户与其他工作线的未提交修改。
- 文档、协议、实现、测试和依赖分开审查；不夹带无关清理。
- 第三方依赖必须精确固定版本，并在引入前完成许可证、安全和供应链记录。
- 未经用户明确要求不提交、不推送、不发布、不更新远端系统。
- 交付汇报列出修改文件、命令、结果、未验证范围和剩余风险。
