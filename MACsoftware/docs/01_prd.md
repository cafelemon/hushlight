# Hushlight Mac 产品需求文档

## 1. 产品目标

让用户无需命令行即可理解并控制小熙与当前 Mac 的连接、权限和本地动作状态。

## 2. M0 用户故事

| ID | 用户故事 | 验收 |
| --- | --- | --- |
| MAC-M0-001 | 用户打开应用后能看到 Bridge 真实状态 | 未接入服务时明确显示“未配置” |
| MAC-M0-002 | 用户能从菜单栏快速查看状态 | 菜单栏图标和文案与主窗口一致 |
| MAC-M0-003 | 用户能一键暂停本地能力 | 暂停后状态立即变为“已暂停” |
| MAC-M0-004 | 用户能理解未来所需权限 | 每项权限展示用途和当前状态，M0 不主动申请 |
| MAC-M0-005 | 用户能查看动作结果 | 没有真实动作时展示空状态，不制造演示记录 |

## 3. 后续主线需求

- M1：应用壳、设备绑定、云端连接、真实暂停拒绝、登录项。
- M2：系统音量、提醒、白名单内容打开。
- M3：网易云音乐适配器与支持版本矩阵。
- M4：微信草稿、联系人消歧、短时确认令牌与防重复发送。
- M5：签名、公证、更新、回滚、诊断与卸载。

## 4. 产品规则

- Bridge 离线不能阻止小熙基础聊天。
- 本地动作只在用户明确请求或接受建议后执行。
- 失败、超时、拒绝和未知结果不得表述为成功。
- 消息发送必须经过草稿、复述、明确确认、真实结果链路。
- 系统权限按需申请；未启用相关能力时不提前索取。
