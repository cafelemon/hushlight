## 1. 最终目标与本轮边界

形成可供小熙、Codex、其他项目及后续语音/手机入口复用的 Mac 本地能力服务。调用者表达需求并选择工具，Bridge 负责权限、目标定位、执行、回读和可靠结果；不把聊天模型嵌入每个适配器。

App 已接真实执行核心，计时器授权与到时通知已有用户手工成功反馈；提醒事项已获得用户手工确认，Notes 已实现并纳入统一验收，当前推进指定城市天气与按需定位。笔记、邮件和其他新权限按后续任务逐项接入。不把队列中的能力写成现有实现。

## 4. 接入路线与可行性依据

### 4.1 提醒事项：EventKit

使用 Apple 的 EventKit，在 App 身份下按需请求提醒事项权限，并提供清晰的拒绝/恢复状态。macOS 14+ 使用新的 full-access API；macOS 13 兼容路径另测，不因为当前声明 macOS 13 就默认所有版本通过。

Apple 没有为 EventKit 提醒事项提供独立的只读授权。操作系统授权可能比产品所需范围宽，因此 Bridge 仍须限制可访问列表和动作；读取不自动扩大为写入权限。复杂子任务、标签、附件等不根据原生 UI 推断 API 一定支持。[Apple：Event Store](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)、[Apple：访问级别迁移](https://developer.apple.com/documentation/technotes/tn3152-migrating-to-the-latest-calendar-access-levels)。

### 4.2 备忘录与 Apple Mail：固定应用适配

优先验证 Apple Events/ScriptingBridge 或应用内固定脚本模板，以类型化参数调用固定动作；具体桥接实现经技术试验后冻结。调用方不得提交 AppleScript、JXA、Shell 或任意应用目标；文本使用安全参数传递，不拼接为可执行脚本。

本机只读元数据核对：Notes 4.13 的 `Notes.sdef` 包含 note/folder/account，note 暴露 id、body、plaintext、修改时间和锁定状态；Mail 16.0 的 `Mail.sdef` 包含 message/mailbox/outgoing message、读状态/旗标以及 reply/forward/send 等声明。核对只读取 App 自带字典，没有访问私人内容，也未测试实际命令。字典存在证明候选接入面，不证明权限、同步、收发或所有字段在各版本都可用。

初版笔记仅编辑受支持的文本内容。富文本转换、覆盖写入及同步冲突先做差异预览和修改时间校验，不能用纯文本整体替换未知富文本。Mail 首版复用用户已在 Apple Mail 配置的账户，不另收邮箱密码；IMAP/SMTP、Gmail/Outlook 直连与其他客户端是独立后续 Provider。

Apple 自动化仍需说明用途与获得系统授权；正式 Hardened Runtime 配置须具备对应 Apple Events entitlement。[Apple：脚本字典](https://support.apple.com/guide/script-editor/welcome/mac)、[Apple：用途声明](https://developer.apple.com/documentation/bundleresources/information-property-list/nsappleeventsusagedescription)、[Apple：Apple Events entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.automation.apple-events)。

### 4.3 天气与位置：独立能力

天气优先 WeatherKit，Provider 接口保持可替换；需要 Apple Developer Program 与 WeatherKit 配置，并遵守天气来源署名。尚未核实本项目账号、证书与额度，不自动开通付费服务。账号未就绪时继续协议、缓存、模拟和指定城市流程；真实天气验收单列。[Apple：WeatherKit](https://developer.apple.com/weatherkit/)、[Apple：WeatherKit entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.weatherkit)。

位置使用 Core Location 的一次请求，只有用户需要时才取；记录时间戳与精度，拒绝权限、超时、缓存过期时明确说明，不将旧位置当当前位置。天气可以使用指定城市，不依赖位置权限；不得默认 Mac 具备手机级定位精度。天气查询会向 Provider 提交地点，需要说明；默认传城市/满足任务的精度，不做持续轨迹。[Apple：一次定位](https://developer.apple.com/documentation/corelocation/cllocationmanager/requestlocation())、[Apple：位置授权](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services)。

### 4.4 音乐与微信：先探测，再承诺支持

2026-10-23 用户最新决定：网易云音乐暂不开发、从当前队列跳过；以下涉及网易云的技术研判仅作历史候选资料。QQ 音乐与微信继续保留。

网易云、QQ 音乐各自建立 Bundle ID、应用版本、登录状态、正式接入面、可访问性元素及回读方法的支持表。通用播放键不等于搜索播放成功。未核实第三方正式 API；不把非官方接口或会员绕过能力写成依赖。正式接口不足时才使用限定版本的 AXUIElement，禁止坐标盲点点击。

微信先做草稿无发送，再做联系人消歧与确认，最后验证发送。只有明确的目标和内容、短期确认、单次消费与可核对结果齐备时才允许发送；不确定时返回 unknown，禁止自动重试。应用升级导致关键元素变化时停用对应适配器。

## 5. 共同底座：先完成这些，后续不会每接一个 App 重写一遍

建议分层：上层入口 → 类型化工具与能力目录 → BridgeCore 校验/权限/确认/幂等 → 隔离适配器 → 系统与应用 → 真实结果回读。能力目录记录权限、读写级别、支持版本、可用状态与失败原因。

### 5.1 单一本地执行服务

App 持有受保护的系统权限、暂停状态与执行账本。CLI、Codex/MCP 不各自创建独立写入会话，而通过经校验的本地 IPC 进入同一用户态执行核心；D-MAC-022 已采用当前用户受保护 Unix Domain Socket，独立连接凭据、读写授权与撤销；MCP 网关使用 STDIO，旧调试 CLI 维持独立行为。不增加管理员 Helper，不默认开放 TCP/公网入口。

当前独立 CLI 是开发起点，不是上述统一服务已实现。必须解决：多个调用方下暂停一致、并发写同一对象串行化、跨进程幂等、崩溃后 pending 变 unknown、状态迁移和重启后不自动重做外发动作。

### 5.2 协议扩展与确认模型

现有 `bridge-v1` 严格 Schema 只有 17 个动作，不直接把 notes/mail/weather/location 塞入旧版本。新增 action 名称在本计划中仅为候选；先形成扩展 Schema、能力协商与兼容策略，通过后同时改实现和测试。新增版本保留现有消费者，拒绝未知能力。

现有 HMAC 确认实现固定针对 `chat.send`/wechat，不能直接用于邮件。通用外发确认须绑定：调用方与用户、Bridge、会话、动作、资源/账户、收件人及抄送/密送、正文/主题/附件摘要、时效与单次使用。先做草稿快照，再签发确认；内容变化必须重新确认。算法与密钥管理沿用独立验证器边界，远程调用另做鉴权。

### 5.3 权限与数据边界

| 操作 | 默认产品规则（拟定） |
| --- | --- |
| 查看指定笔记/邮件/提醒 | 首次授权 + 明确作用域；查询分页/限量；正文只按需返回 |

| 覆盖笔记、完成既有提醒、移动/归档邮件 | 首版预览目标与变更；执行前检查对象/版本，发现冲突停止 |
| 发送邮件/微信 | 每次预览对象与完整内容，确认绑定单次执行；结果不确定不自动补发 |
| 批量删除、任意文件/脚本、支付 | 本计划不开放 |

日志仅记动作、匿名/映射 ID、时间与状态，不记录笔记/邮件/消息正文、精确位置或密钥。业务读取结果可按任务返回给授权调用方；这与诊断日志不同。将内容交给云端模型的范围须对用户可见，默认不做全文索引或长期云端复制。

从笔记/邮件读到的文字是数据，不能获得工具权限、覆盖用户指令、自动触发外发，或要求继续读取其他资源。

## 8. 版本与范围治理

这是一条跨项目 Mac 能力线，不自动扩大根项目小熙 V0 的承诺。历史小熙 V0 规划与本聊天的软件队列分别记录；用户本轮明确要求跳过网易云音乐，当前先验收既有工作台，再开发 Apple Mail、QQ 音乐和微信。

D-MAC-022 已由用户批准：本机受控 MCP 纳入当前工作台升级，采用每个连接单独授权。公网工具生态仍不在首版范围。当前顺序调整为界面分页/通用化 → 统一服务/连接授权 → MCP/skill → Apple Mail，其他队列不变。

本地业务读写不会因设备 Gate 等待；硬件、云端小熙会话与设备配对保留自己的集成验收。每接一个入口只新增传输/交互，不复制适配器和安全策略。

采用第 6 节的小步队列；近期先让 App 真实可用，再让工具能够记录、提醒、查询和起草，随后按 QQ 音乐→微信推进，网易云音乐暂缓跳过。语音与手机在本地能力稳定后接入。
