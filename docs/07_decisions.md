### D-002 陪伴为本，行动按需

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-09 |
| 决策 | 小熙首先提供工作之外的自然陪伴；用户明确提出或接受建议后才执行动作 |
| 原因 | 用户调研更偏向陪伴、聊天、音乐和状态调节；工作助手定位会削弱购买动机 |
| 影响 | IDE、Git 和复杂办公工作流退出 V0 |

### D-003 保留并产品化 PC Bridge

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-09 |
| 决策 | PC Bridge 是完整体验的第一方组件；基础聊天可在 Bridge 离线时降级运行 |
| 原因 | 音乐、本地系统和聊天控制具有较强用户吸引力；竞品证明可行但产品化粗糙 |
| 影响 | 必须提供安装包、托盘壳、权限引导、更新、回滚、诊断和卸载，不接受压缩包命令行交付 |

### D-004 Web 是产品大本营

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-09 |

| 影响 | Bridge 只保留必要本地壳，不重复建设完整配置中心 |

### D-005 首批本地能力

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |

### D-006 本地接入优先于昂贵或受限的云连接

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-09 |
| 决策 | 优先使用系统正式接口、应用正式接口和本地适配器；云端 API 仅在开放、稳定、合规且成本可接受时使用 |
| 影响 | 每个应用独立适配；UI 自动化只作为最后路径并受版本限制 |

### D-007 消息发送必须确认

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-09 |
| 决策 | 消息采用“草稿 → 复述对象和内容 → 用户确认 → 发送 → 返回真实结果” |
| 原因 | 在减少操作和避免误发送之间保留最低必要确认 |
| 影响 | 首版不提供永久免确认发送 |

### D-008 多款前端风格不进入 V0 必选

### D-009 用户偏好功能丰富，但安全底线不可省略

|---|---|

| 影响 | 安全设计以低摩擦护栏呈现，不以用户主动配置为前提 |

### D-010 macOS 与 Windows 双线并行

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-11 |
| 决策 | V0 同时开发 macOS 与 Windows Bridge；项目发起人负责 macOS，另一名开发者负责 Windows |

| 影响 | 两端可以独立选框架，但必须共享工具、权限、确认、错误和结果契约，并分别完成验收 |

### D-014 H0 采用两台 Korvo-2 参考设备

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-11 |
| 决策 | H0 保留两台 ESP32-S3-Korvo-2 V3.1 参考设备，采用官方 2.4 英寸触控屏、双麦、4Ω/3W 扬声器和 USB-C 常供电；分别供 macOS、Windows 软件线立即联调 |
| 原因 | 优先验证完整音频、角色表现和 Bridge 闭环，同时避免把开发板成本与消费版 BOM 混为一谈 |
| 影响 | Korvo-2 不再代表目标产品结构；它负责保障软件进度，并在自研板切换后保留为参考、回归和故障回退设备 |

### D-016 H0 与消费版成本边界

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-11 |
| 决策 | 两台 Korvo-2 参考设备实际支出目标不高于 2000 元、绝对上限 2500 元；自研 PCB/双轴/结构线独立报价审批；消费版千台级 BOM 仍以不高于 150 元为目标并重新验证；249 元活动价下首购硬件不得依赖月卡补亏 |
| 原因 | 研发板用于降低技术风险，不能直接代表量产成本；竞品低价要求项目尽早验证成本通路 |
| 影响 | Korvo-2 不得直接进入量产；摄像头和双轴的 BOM 增量必须单列；两条硬件线采购、付费唤醒词服务和正式定价仍需分别审批 |

### D-017 H0 采用固定底座与双轴屏幕/摄像头

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-11 |
| 决策 | 双轴云台收益高于风险。底座固定，运动件仅为屏幕、摄像头及必要支架/线束；待机关闭摄像头且不跟随，主动唤醒和对话期间才进行端侧定位、平滑跟随和有语义的角色动作 |
| 原因 | 双轴提供更准确的对话朝向、更大桌面工作区覆盖和更丰富的身体语言，能直接增强电脑旁的陪伴感 |
| 影响 | 必须加入大死区、轨迹规划、限位/急停、有限搜索、端侧图像处理、摄像头工作指示和物理遮挡；运动不能破坏唤醒与 AEC |

### D-018 自研硬件成为并行主线

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-11 |
| 决策 | 硬件工程师并行负责自研 PCB、板级调试、3D 打印结构、双轴云台和整机交接；至少 3 块同版本稳定工程板通过切换 Gate 后，成为硬件工程师、macOS 和 Windows 开发的主要设备 |
| 原因 | 研发样机需要尽早验证真实成本、结构、运动和可交接性，同时不能让首板或机械延期阻塞软件开发 |
| 影响 | 设备软件建立 `korvo2_ref` 与 `hushlight_h0_custom` 统一 BSP；切换前 Korvo-2 保障软件，切换后仍负责差异回归和回退 |

### D-019 H0C Rev A 采用三实时域与效果优先器件基线

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-08-12 |
| 决策 | H0C Rev A 不以单颗 ESP32-S3 承担整机功能；采用 BASE-S3 音频/联网、HEAD-S3 高清显示/视觉、MOTION-C3 双轴闭环三域架构。自研首板使用 2.41 英寸 600×450 AMOLED 成熟模组及自研 Head Carrier，正式供电提升为 USB-C PD 12V/3A，并分出 Head/Motor 可关断电源域 |
| 原因 | 第一版以生命感、跟随平滑度、音频稳定性和首板成功率为先；视觉、网络和电机负载需相互隔离，避免单主控资源争用和跨域回归 |
| 影响 | `10_hardware_board_design_spec.md` 成为板级权威；09 中 5V/2A、320×240、自研单主控与数字麦假设被取代。摄像头、角度传感器、电机、eFuse 和 AMOLED 扩展 GPIO 仍须在 G0/G1 Gate 实测冻结 |

## 2. 待决策

### O-002 Bridge 框架

macOS 与 Windows 可以采用不同框架。候选需要比较：原生能力、安装包签名、托盘/菜单栏、系统权限、自动更新、包体、崩溃恢复、契约复用和各自开发者熟悉度。下一轮硬件方向后进入技术研判。

### O-006 模型和成本路由

需要确定 ASR、普通对话、复杂对话、情绪策略和 TTS 的供应商、限额、失败切换和单位成本。属于技术层面，下一轮硬件方向后再确认。

### O-008 月卡和免费额度

当前不做决定。后续根据真实语音轮次、云成本、本地适配维护成本和用户反馈判断；客服报价或口头付费意愿不能替代真实验证。

### O-009 自研板技术与预算细节

硬件工程师需要通过评审冻结具体摄像头、屏幕连接、电机/驱动/编码或限位、电源与音频隔离、原理图、PCB、BOM、打样数量、首板排期和独立预算。双轴方向与双线策略已经确认，这些技术细节不得反向取消软件参考线。
