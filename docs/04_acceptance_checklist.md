> 文档版本：V0.5

## 1. 验收规则

- 自动测试通过不等于用户验收。
- 子任务必须分别完成开发、测试和验收，才能进入集成验证。
- 所有证据必须记录版本、平台、日期和执行人。
- “演示成功一次”不能替代重复测试和失败路径验证。
- 未实现、待复核和环境受限必须明确标记，不得按通过处理。
- 发布、推送、上线和生产验收是不同状态。
- 离线测试、模拟适配器、本机 MLX 评测和开发构建只能证明其对应技术事实，不能替代真实账号/应用、用户、生产或付费验收。
- V0 用户完整闭环以 macOS 为准；Windows 和 H0C 分别只按本清单的限定 Gate 计入完成度。

## 8. 消息发送安全 Gate

以下任一项失败，V0 不得通过：

- [ ] 草稿生成不产生外部影响。
- [ ] 联系人不唯一时停止并要求消歧。
- [ ] 发送前复述联系人和完整内容。
- [ ] 用户明确确认后才生成短时确认令牌。
- [ ] 草稿修改后旧确认失效。
- [ ] 超时、断网或软件状态未知时不发送。
- [ ] 同一请求重复到达不会重复发送。
- [ ] 未确认发送数为 0。
- [ ] 测试账号和测试联系人不涉及真实外部对象。

## 11. V0 最终结论

| 结果 | 条件 |
|---|---|
| Go | 必须项全部通过，核心假设得到用户证据支持 |
| Go with actions | 无安全和误发送问题；存在有 Owner 和期限的非阻断修正 |
| Revise | 核心体验可改进，但当前证据不足以进入 Alpha |
| No-Go | 用户不需要硬件陪伴、拒绝 Bridge、行动不可靠或成本不可持续 |

评审结果、版本和签字人记录在 `06_progress.md`，重大原因写入 `07_decisions.md`。
