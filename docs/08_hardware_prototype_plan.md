## 1. 结论与阶段边界

H0 采用两条并行硬件路线：两台 Korvo-2 参考设备保证软件开发立即启动；硬件工程师同步负责自研 PCB、3D 打印结构、双轴云台和整机落实。

自研工程样板通过切换 Gate 后成为 macOS、Windows 软件开发的主要设备，Korvo-2 保留为参考、回归和延期兜底设备。

本文统一使用以下名称：`PC Bridge` 指安装在 macOS/Windows 上的本地执行程序；“Web 大本营”指账户、设备、配置、权限和完整诊断入口；“研发诊断页”仅指设备端由长按进入的 H0 本地测试页面，不替代 Web 大本营。

| 项目 | 已确认规则 |
|---|---|
| 参考设备 | 2 台 Korvo-2；macOS、Windows 开发线各 1 台 |
| 自研主线 | 切换前至少 3 块同版本稳定工程板；硬件工程师、macOS、Windows 各 1 块 |
| 软件周期 | `T0` 后 4–6 周；`T0` 为两台同版本参考设备到货、验收且台架条件可用之日，不等待自研板 |
| 自研周期 | 硬件工程师提交 PCB、结构、云台和首板排期；不得成为软件 V0 的前置依赖 |
| 结构 | 固定底座 + 双轴轻量头部；PETG 模块壳，可拆装、可返工；不开模 |
| 供电 | USB-C 5V/2A 常供电；无电池 |
| 消费版边界 | 不设计包装，不冻结最终 ID，不做认证或量产承诺 |
| 完成口径 | 参考设备先通过软件 H0 Gate；自研板通过切换 Gate 后成为主要开发设备；均不等于用户验收或 V1 Alpha 完成 |

## 2. 目标与非目标

H0 只验证进入 V0 集成所需的设备能力，不承接消费版设计和量产任务。

双轴云台收益高于当前风险，是 H0 已确定方向。H0 Gate 验证实现质量和 V1 准入条件，不重新决定是否研发双轴。

### 2.1 H0 目标

- 跑通本地唤醒、双麦前处理、AEC、云端聊天、TTS 播放和自然打断。
- 验证角色面孔、触摸反馈、本地动画和双轴身体语言能否形成高于竞品文本屏的陪伴感。
- 让设备在 PC Bridge 离线时仍可聊天，在 PC Bridge 在线时调用网易云音乐、微信等本地能力。
- 用 Korvo-2 参考设备保证 macOS、Windows 软件开发不因 PCB、结构或云台延期而停工。
- 由硬件工程师完成自研 PCB、3D 打印结构、双轴云台、板级调试和可交接工程样板。
- 自研工程样板稳定后，切换为软件团队的主要设备，并保留参考设备执行差异回归。

### 2.2 H0 不做

- 消费版外观、材料工艺、包装、开模、认证和小批量生产。
- 电池、移动使用、待机视觉跟随和持续环境录像。
- 将 Korvo-2 直接作为量产主板。
- 冻结月卡、免费额度或模型供应商。

H0 的摄像头只在唤醒和对话期间用于端侧人脸位置判断。待机不跟随，摄像头不持续分析；不上传、不保存原始图像。PIR/毫米波等无摄像头在场感知仍在 V1 Alpha 前独立研判。

## 3. 双线硬件基线

两条线共享产品行为和 BSP 契约，但使用不同的板级实现与 Gate。

### 3.1 Korvo-2 参考设备线

| 子系统 | 参考设备基线 | 约束 |
|---|---|---|
| 主板 | 2 × ESP32-S3-Korvo-2 V3.1 | 两台采购同一硬件版本；8 MB Flash / 8 MB PSRAM 版本为当前基线 |
| 显示 | 2 × 官方 ESP32-S3-Korvo-2-LCD | 2.4 英寸、320×240、SPI、电容触控，横屏安装 |
| 收音 | Korvo-2 板载双麦 + ES7210 | 保留官方 AEC 参考通路，不外接不同型号麦克风 |
| 播放 | ES8311 + NS4150 + 40 mm、4Ω/3W 全频扬声器 | 可拆密闭音腔，扬声器与麦克风隔振 |
| 控件 | EC11 旋钮、锁定式静音开关、红色静音灯 | 通过 MCP23017 接入，不复用音频 GPIO |
| GPIO 扩展 | MCP23017，计划 I2C 地址 `0x21` | 台架扫描总线确认无冲突后冻结地址 |
| 供电 | 后置 USB-C 5V/2A | 面板转接至主板电源口；日常使用一根线 |
| 服务接口 | Micro-USB/UART 与 USB 配置口 | 藏于可拆服务盖板内，仅用于刷机、日志和配置 |
| 结构 | 模块化台架或 PETG 参考壳 | 不等待自研云台结构；可外接摄像头和运动控制测试模块 |

主板选择依据：Korvo-2 已集成双麦、ES7210、ES8311、3W 功放、LCD 和摄像头接口，并提供 AEC 参考通路，适合先验证完整语音链路。[乐鑫 Korvo-2 官方资料](https://docs.espressif.com/projects/esp-adf/en/latest/design-guide/dev-boards/user-guide-esp32-s3-korvo-2.html)

官方扩展屏为 2.4 英寸 320×240 SPI LCD，并带电容触控。[乐鑫 LCD 官方资料](https://docs.espressif.com/projects/esp-adf/en/latest/design-guide/dev-boards/user-guide-esp32-s3-korvo-2-lcd.html)

### 3.2 自研硬件主线

| 子系统 | 自研工程样板基线 | Owner / 约束 |
|---|---|---|
| 主控 | ESP32-S3-WROOM-1-N16R8 为首选，硬件工程师在原理图评审时确认 | 16 MB Flash 用于角色资源和 OTA 余量；8 MB PSRAM 支撑音频、显示和视觉缓存 |
| 音频 | 双路同型号 MEMS、ES7210、ES8311、3W 功放和 AEC 参考回采 | 固定底座；参考 Korvo-2 已验证链路，不因头部运动改变声学位置 |
| 显示 | 2.4 英寸 320×240 横屏触控 | 安装在双轴轻量头部；驱动通过统一 BSP 接口 |
| 摄像头 | 安装在屏幕头部，具体 Sensor/FPC 在硬件技术评审冻结 | 只做端侧人脸位置；必须有工作指示和物理遮挡能力 |
| 双轴运动 | 水平 + 俯仰；电机、编码/限位、驱动方案由硬件工程师冻结 | 运动件仅包含屏幕、摄像头和必要支架/线束 |
| 固定底座 | 主 PCB、麦克风、扬声器、音腔、电源、物理控制和重心 | 电机供电与音频供电隔离/滤波，避免振动和电噪声破坏 AEC |
| 调试与量产准备 | USB-C、串口/USB 调试、测试点、版本识别和可恢复刷机 | 首板即保留板级诊断和后续生产测试接口 |
| 结构 | 3D 打印固定底座、双轴头部、可拆音腔和服务盖板 | 硬件工程师负责 CAD、装配、限位、线束和结构版本 |

自研主线不是远期量产研究，而是 V0 并行研发主线。第一版稳定工程板通过切换 Gate 后，软件团队必须将它作为主要设备；Korvo-2 继续承担参考与回退，不继续扩展成产品结构。

## 4. 结构与声学规则

```text
固定底座
├── 主 PCB、双麦、扬声器和可拆密闭音腔
├── 电源、运动驱动、静音开关、红灯和 EC11 旋钮
├── 后置 USB-C 供电口、调试口和服务盖板
└── 水平旋转轴、重心和防滑支撑

双轴轻量头部
├── 2.4 英寸横屏与触控
├── 摄像头、工作指示灯和物理遮挡片
├── 俯仰轴、机械限位和柔性线束
└── 运动件仅限屏幕、摄像头及必要支架/线束
```

- 麦克风拾音孔不得被屏幕框、装饰件或防尘网胶层遮挡。
- 麦克风孔径、壳体厚度、密封套、防尘和隔振按乐鑫建议设计；首轮结构件记录实际孔径和密封材料。
- 扬声器音腔使用软垫与主壳隔振，音腔容积作为可替换结构参数，不与主壳一体封死。
- 待机时头部保持预设休息位，不跟随、不巡视；唤醒或主动进入对话后才允许摄像头和双轴运动工作。
- 摄像头工作时指示灯必须可见；物理遮挡片关闭后不得产生有效图像帧。
- 双轴必须有软限位、机械限位和失控停机策略；丢失目标后只允许一次有限搜索，不得持续扫描房间。
- 视觉坐标不得直接逐帧驱动电机，必须依次经过意图滤波、死区判断、轨迹规划和电机控制。
- 聆听和录音敏感阶段优先停止电机，避免运动振动与电噪声破坏唤醒、识别和 AEC。
- 预留在场传感器可拆盖板和走线空间，但不承诺具体传感器尺寸与接口。

声学结构依据：[乐鑫麦克风设计指南](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/audio_front_end/Espressif_Microphone_Design_Guidelines.html)。

## 5. 固件状态与输入契约

以下状态和输入是设备、云端、PC Bridge、角色动画和测试共享的 H0 契约。

### 5.1 正交状态模型

业务状态同时只能存在一个：

| 业务状态 | 用户可见表现 | 核心规则 |
|---|---|---|
| `Idle` | 平静角色与低频微动画 | 只运行本地待机、唤醒和必要连接逻辑 |
| `Listening` | 明确聆听表情 | 采集并发送唤醒后的语音 |
| `Thinking` | 思考表情 | 不伪造动作或聊天结果 |
| `Speaking` | 角色说话动画 | 支持触摸或语音打断 |
| `Action` | 简短行动反馈 | 只展示用户可理解状态，不显示工具日志 |

隐私、连接和故障是独立维度：

| 维度 | 状态 | 规则 |
|---|---|---|
| 麦克风隐私 | `MicEnabled` / `Muted` | `Muted` 停止采集；解除后业务状态回到 `Idle`，不自动录音 |
| 云端连接 | `Online` / `Offline` | `Offline` 保留本地交互，禁止发起云端聊天和远程行动 |
| 健康状态 | `Healthy` / `Error` | `Error` 停止受影响能力，复杂诊断进入 Web 大本营或研发诊断页 |
| 摄像头隐私 | `CameraOff` / `CameraActive` / `CameraBlocked` | `Idle` 必须为 `CameraOff`；物理遮挡时为 `CameraBlocked`，禁止视觉跟随 |
| 运动状态 | `Resting` / `Acquiring` / `Tracking` / `Gesture` / `MotionFault` | 待机为 `Resting`；故障立即停机，不影响基础语音和屏幕交互 |

设备日志必须同时记录业务状态与五个正交维度。主视觉优先级为 `Muted > Error > Offline > 业务状态`；低优先级维度可保留为角标，但不得覆盖静音状态。PC Bridge 在线状态不属于设备连接维度，由行动能力状态单独显示。

### 5.2 输入

| 输入 | 状态条件 | 行为 |
|---|---|---|
| 旋钮旋转 | 健康状态为 `Healthy` | 调整设备播放音量 |
| 旋钮短按 | 存在待确认操作 | 确认当前操作；无待确认时不扩大权限 |
| 旋钮长按 | `Idle` | 唤醒并进入 `Listening` |
| 旋钮长按 | `Listening`、`Thinking`、`Speaking` 或 `Action` | 取消当前聆听、播报或行动候选 |
| 轻触角色 | `Idle` | 唤醒并进入 `Listening` |
| 轻触角色 | `Speaking` | 停止播报并进入 `Listening` |
| 屏幕长按 | 麦克风隐私状态非 `Muted` | 进入研发诊断页 |
| 静音开关打开 | 任意组合状态 | 300 ms 内将麦克风隐私状态置为 `Muted`，停止采集并亮红灯 |
| 静音开关关闭 | 麦克风隐私状态为 `Muted` | 将隐私状态置为 `MicEnabled`，业务状态返回 `Idle`；必须再次主动唤醒 |

静音开关优先于触摸、旋钮、唤醒词和远程命令。H0 使用锁定开关与固件强制静音；消费版自定义 PCB 必须升级为真正切断麦克风硬件通路。

### 5.3 视觉跟随与运动契约

| 阶段 | 摄像头与头部行为 | 退出条件 |
|---|---|---|
| `Idle` / 待机 | 摄像头关闭，头部保持休息位，不跟随、不搜索 | 本地唤醒词、旋钮长按或轻触角色 |
| 唤醒后定位 | 摄像头开启并显示工作指示；在限定角度和时间内寻找当前对话者 | 找到目标进入跟随；超时执行一次有限搜索后停止 |
| 对话跟随 | 使用大死区和低速平滑轨迹，只在目标持续偏离时调整水平/俯仰 | 对话结束、静音、遮挡、目标丢失或运动故障 |
| 角色动作 | 点头、轻微歪头、低头等预编排动作；不得与跟随控制抢占电机 | 动作完成后回到跟随或休息位 |
| 隐私/故障 | 摄像头关闭或无有效帧；电机停止并回到可达的安全位 | 用户重新唤醒且隐私与健康状态允许 |

视觉只输出目标位置、置信度和时间戳，不向云端、Web 或 PC Bridge 输出原始图像。跟随、角色动作和安全停机由统一运动仲裁器管理，任何单个算法模块都不得绕过限位和速度约束。

## 6. 角色表现力

- 屏幕常态显示角色面孔，不显示 API、MCP、工具调用日志或长文本。
- 首轮至少提供平静、开心、关切、思考、惊讶、困倦、歉意、俏皮 8 类表现。
- 本地微动画至少包含眨眼、呼吸、视线移动、触摸反馈和基于播放振幅的说话动画。
- 双轴身体语言至少覆盖轻点头、轻微歪头、思考低头和唤醒抬头，并与屏幕表情使用同一角色状态，不做无语义的持续摆动。
- 动画、触摸反馈和短音效本地运行，不因待机表现调用云服务。
- 屏幕只在必要时显示一行短状态；账户、设置、权限、完整行动结果和诊断归 Web 大本营或 PC Bridge。
- H0 用同一组五个陪伴/行动场景与本地竞品视频比较，验证“角色生命感”而不是工具数量。

## 7. 联网、PC Bridge 与唤醒

- USB 配置是 H0 正式配网方式；BLE 能力保留，但不进入首轮 Gate。
- PC Bridge 离线时，设备仍通过 Wi-Fi 使用基础云端聊天；本地软件能力明确不可用。
- PC Bridge 或适配器返回失败、未知或超时时，设备不得播报成功。
- 最终本地唤醒词必须为“小熙”。早期台架允许官方占位词或旋钮/触摸联调，但占位词不能通过 H0 最终 Gate。
- 第 1 周并行启动“小熙”模型申请或训练。传统乐鑫定制流程可能需要 2–3 周；任何付费服务单独报价、单独批准，不计入硬件预算。[WakeNet 定制说明](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32s3/wake_word_engine/ESP_Wake_Words_Customization.html)

ASR、LLM、TTS 供应商和协议实现属于下一轮技术研判，本计划只冻结设备可见行为和失败边界。

## 8. 成本与版本治理

研发样机成本、消费版成本假设和双机版本分别记录，不得互相替代。

### 8.1 Korvo-2 参考设备预算

| 口径 | 边界 |
|---|---|
| 两台参考设备实际支出目标 | 不高于 2000 元 |
| 两台参考设备绝对上限 | 2500 元 |
| 包含 | 主板、屏幕、扬声器、控件、电源转接、线材、结构打印和必要返工 |
| 不包含 | 人工、云 API、另行批准的唤醒词服务 |
| 采购规则 | 提交含税到手报价并获得采购批准后执行；不得用预算上限替代报价 |

审批规则：报价不高于 2000 元仍须取得首次采购批准；超过 2000 元且不超过 2500 元时，必须提交差异原因并由项目发起人再次批准；超过 2500 元立即停止采购并重新评审方案。

海外经销商当前挂牌参考约为主板 50 美元、LCD 32 美元/套；该价格不含国内运费和税，仅用于预算校验，采购时必须重新核价。[DigiKey 主板](https://www.digikey.com/en/products/detail/espressif-systems/ESP32-S3-KORVO-2/15822448)、[DigiKey LCD](https://www.digikey.com/en/products/detail/espressif-systems/ESP32-S3-KORVO-2-LCD/17887515)

### 8.2 自研主线预算

- 自研 PCB、打样贴片、屏幕/摄像头、电机与驱动、3D 打印、线束、夹具和返工单独编制 BOM 与含税报价，不计入两台参考设备的 2500 元上限。
- 硬件工程师在原理图评审前提交首板预算、最小打样数量、交期和主要成本风险；未获批准不得采购、下单或制作。
- 首轮至少规划 3 块可交接工程板的成本，但批准数量以正式报价为准。
- 摄像头和双轴云台带来的消费版 BOM 增量必须单列，不得用订阅收入掩盖硬件亏损。

### 8.3 消费版成本假设

- 299 元日常价、249 元活动价是立项价格目标，不是正式定价。
- 千台级消费版整机 BOM 当前以不高于 300 元为成本上限；必须分别核算 Head、Base 音频、电机/编码/传动、结构、线束/电源与质保损耗，不得以任何单一开发模组零售价替代量产 BOM。
- 消费版 Head 基线为自研 `ESP32-S3 + 2.4 英寸 320×240 IPS 电容触控屏`；600×450 AMOLED 自研 Head 只保留为市场反馈触发的后续版本候选。两者均须以供应商 RFQ、样件与用户效果证据验证，不得凭网页价格冻结。
- `AC-H0-CST-002` 的消费版成本部分新增 `H-CST-001`：Head、Base 音频、运动/传动、结构、线束/电源、制造损耗与质保必须形成同一千台级、含税口径的分项 BOM；在总额 ≤300 元前，IPS 路线只是一项成本假设，不是已证明结论。
- 249 元活动价下，扣除税费、渠道/支付、履约和质保准备后的首购硬件贡献不得为负。
- 月卡主要覆盖聊天额度、云服务和持续运营，不作为填补硬件亏损的前提。
- 进入 V1 Alpha 前必须完成自研板成本通路评估；Korvo-2 方案不得直接进入量产。

### 9.3 统一板级接口

设备上层应用只允许依赖统一 BSP，不得直接判断具体板卡并散落条件分支。首轮必须提供 `korvo2_ref` 与 `hushlight_h0_custom` 两个实现，覆盖：

- `audio_capture`、`audio_playback` 与 AEC 参考通路；
- `display`、`touch`、旋钮、按键和静音；
- `camera` 的启停、遮挡和目标位置输出；
- `motion` 的休息位、跟随目标、角色动作、限位和急停；
- `power`、版本识别、日志、诊断和可恢复刷机。

`h0-bsp-v1` 由设备固件 Owner（待指定）负责冻结和版本治理。硬件工程师负责 `hushlight_h0_custom` 实现，设备固件 Owner 负责 `korvo2_ref` 实现和上层兼容。

契约至少定义每个接口的输入、输出、错误码、超时/时序、能力发现、版本兼容和接口测试。变更必须升级契约版本并完成两套 BSP 回归。

## 12. 进入 V1 Alpha 前的停止条件

以下任一项未关闭，不得把 H0 直接推进为封测设备：

本节用于判断实现质量与 V1 准入，不重新打开 D-017 已批准的双轴研发方向。若某项失败，应修正实现、明确降级或停止进入 V1，而不是默认取消 H0 双轴主线。

- 无法证明消费版整机千台级 BOM 可不高于 300 元。
- “小熙”本地唤醒在真实壳体中无法达到 H0 指标。
- AEC、静音或长稳 Gate 失败。
- 参考设备长期分叉，或自研板无法通过统一 BSP 和切换 Gate，导致跨平台结果不可比较。
- 待机摄像头无法可靠关闭，物理遮挡/工作指示不成立，或丢失目标后仍持续扫描。
- 双轴运动明显破坏唤醒、AEC、稳定性或线束寿命，且没有可验证的降级方案。
- 角色表现力对比未达到 7/10，且没有明确的可验证改进方案。
- 在场感知、硬件级断麦、OTA、认证和量产测试尚未形成 Alpha 方案。
