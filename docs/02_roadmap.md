## 1. 阶段总览

| 阶段 | 目标 | 主要交付 | 进入下一阶段条件 |
|---|---|---|---|
| K0 立项 | 冻结命题、范围、实现边界和证据口径 | 评审记录、决策、架构、验收与工作包责任表 | K0 Gate 通过 |
| V0 体验验证 | 证明陪伴 + 本地轻行动有价值 | macOS 完整闭环、Windows 基础产品化、Web、H0 内部样机、10-20 人免费测试 | V0 Gate 通过 |
| V1 Alpha | 形成可封测产品 | 设备原型、稳定语音、记忆、主动关怀、50-100 人封测 | Alpha Gate 通过 |
| V1 Pilot | 验证小批量商业化 | 小批量硬件、订阅、升级、诊断、合规和售后 | Pilot Gate 通过 |

本基线采用 K0 收口 2 周、V0 体验验证 16 周；以 macOS 云端完整闭环为关键路径。具体日历起点、采购交期和外部服务等待须在启动时另行记录，不以本表替代授权。

### V0 评审节点

1. 交互原型评审：首次使用、陪伴、音乐和消息发送。
2. 概要设计评审：Bridge 工具协议、状态和失败处理。
3. 自研硬件评审：原理图、PCB、BOM、摄像头、云台、3D 结构、BSP、独立预算与切换条件；仅形成内部联调资格。
4. 功能规格评审：每个适配器的输入、权限和通过条件。
5. 子任务验收：每个工作包完成开发、测试和验收。
6. 集成验证：所有纳入 V0 的工作包验收完成后开始。
7. Go/No-Go 评审：依据 `04_acceptance_checklist.md`。

macOS Bridge 内部使用 S1 局域网研发、S2 云端完整闭环、S3 正式产品准备三阶段。S1/S2 属于 V0 软件验证；S3 在功能冻结后形成 V1 Alpha 可交付基线，不改变项目级阶段名称。

AI 原方案的 12 周计划只作为一条并行工作线假设：第 1 周 Schema、第 2～3 周 Gold Set、第 3 周基线、第 4～6 周 Seed SFT、第 7～11 周扩展和 DPO、第 12 周设备闭环。它不替代项目总周期，也不能绕过数据许可、训练资源、模型收益和安全 Gate。

### V0 No-Go

- 非技术用户仍需要命令行或手动配置。
- 陪伴体验与普通聊天应用无明显差异。
- 音乐和轻行动失败率导致用户不再信任。
- 消息确认不能稳定阻止误发送。
- 用户普遍拒绝安装或授权 Bridge。
- 云端 Provider 成本或故障降级无法支持免费种子测试，且没有可接受的限额方案。

## 4. V1 Alpha

### 范围候选

- 由 H0 自研主线演进的封测级桌面设备。
- 真实扬声器场景下 AEC 和自然打断。
- Bridge 正式产品准备：macOS S3 完成官网 Developer ID DMG、公证、Sparkle 更新、回滚和卸载；Windows 采用独立平台方案。
- 稳定结构化记忆和引用解释。
- 主动关怀策略与频率学习。
- 第二个本地平台或第二组适配器，仅在 V0 证据支持时加入。
- 50 至 100 名成年用户封测。

### Alpha Gate

- P95 首段语音低于 2.8 秒。
- 设备连续运行 7 天无严重崩溃。
- Bridge 安装、更新、暂停和卸载通过。
- 未确认外部动作数为 0。
- 用户能区分陪伴价值和自动化价值。
- 主动关闭率、记忆纠正率和云成本进入可接受区间。
- 安全红队、隐私删除和工具注入测试通过。

## 5. V1 Pilot

### 范围候选

- 小批量结构、声学和生产测试。
- 设备注册、证书、OTA、灰度和回滚。
- 月卡、用量、免费额度和成本路由。
- 数据导出、删除、投诉和售后诊断。
- 应用签名、分发和版本支持策略。
- 200 至 500 台试销。

### Pilot Gate

- 完成适用的合规评估和发布签字。
- 硬件不良率、退货率和售后成本可接受。
- 活跃用户单位经济性符合套餐。
- Bridge 和适配器更新不会破坏核心陪伴。
- 售后、回滚、删除和应急流程可运行。

## 6. V2 候选

- Windows/macOS 双平台完整支持。
- 更多音乐和聊天适配器。
- 多款 Web 与设备角色风格。
- 可选开放工具生态。
- 手机端轻入口。
- 视觉、运动或轻触觉的后续扩展能力。
- 企业或创作者扩展能力。

V2 候选不属于当前承诺。
