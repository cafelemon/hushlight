## 2. 开发前

每个任务开始前必须：

1. 检查仓库指令、工作树状态和当前分支。
2. 阅读任务对应的 PRD、架构、验收和决策条目。
3. 明确任务范围、非范围、可见行为和失败路径。
4. 检查是否存在用户未提交或未跟踪的修改。
5. 不清理、不覆盖、不批量暂存无关变化。
6. 未冻结的平台、供应商和技术栈不得被默认为长期承诺。

## 3. 子任务完成定义

一个子任务只有同时具备以下内容才算完成：

- 实现完成。
- 相关单元、集成或界面测试通过。
- 对应验收项有证据。
- 失败和降级路径经过验证。
- 文档、配置和版本信息同步。
- 没有遗留未说明的高风险事项。

测试通过不是用户验收。所有子任务完成后才能开始集成验证。

## 4. 产品规则保护

### 陪伴

- 不把每次负面表达转成任务。
- 用户拒绝后停止建议。
- 不生成排他、挽留、诊断或操纵话术。
- 低置信度必须澄清。

### 工具

- 工具必须注册、版本化、Schema 校验并声明权限等级。
- 工具结果是执行状态的唯一事实来源。
- 禁止模型自行声称动作已经完成。
- 未注册工具、任意 Shell 和 L4 动作必须在接口层拒绝。

### 消息

- 草稿与发送必须是两个独立操作。
- 联系人和正文必须展示或复述。
- 发送需要绑定参数摘要的短时确认令牌。
- 超时、断网、状态不明和重复请求不得发送。

### Bridge

- 不向用户展示命令行、端口、MCP 或内部配置。
- 新能力必须有权限说明、状态入口、失败提示和卸载影响说明。
- UI 自动化不允许使用未经验证的固定坐标盲操作。
- 适配器失败不得影响基础聊天和其他适配器。

## 5. 数据和凭据

- `.env`、令牌、证书、账号、聊天正文和个人数据不得提交。
- 测试使用虚构账号、联系人和内容。
- Bridge 令牌使用系统安全存储。
- 日志默认脱敏联系人、正文、路径和凭据。
- 原始语音默认不长期保存。
- 删除记忆后必须验证检索和生成均不再引用。

## 6. 代码与架构约束

- 设备、云端、Web、Bridge 和适配器保持清晰边界。
- 每个本地应用使用独立适配器，不在核心编排中写应用特例。
- 请求使用稳定 `request_id` 贯穿会话和工具链路。
- L3 动作要求幂等和确认令牌。
- 协议、Schema、工具和适配器必须版本化。
- 外部供应商通过 Adapter 接入，不把业务逻辑绑定单一 API。
- 早期优先模块化单体，不因未来规模假设提前拆微服务。

### 双平台协作

- macOS 与 Windows 由不同开发者并行推进。
- 两端可以采用不同框架，但必须共享工具名、参数 Schema、权限等级、确认语义、错误码和结果 Schema。
- 跨平台契约先于平台实现冻结；平台差异使用显式扩展字段，不修改公共语义。
- 网易云音乐和微信分别维护 macOS、Windows 支持版本矩阵。
- 一个平台完成开发、测试和验收，不代表另一个平台完成。
- 双平台子任务分别验收后，才进行公共场景集成验证。

### 双线硬件协作

- 硬件工程师拥有自研 PCB/BOM、板级调试、摄像头与运动电气、3D 结构、双轴云台、整机装配和板级交接责任。
- 设备软件只依赖统一 BSP；必须维护 `korvo2_ref` 与 `hushlight_h0_custom` 两个实现，不在业务层散落板卡条件分支。
- 自研板通过切换 Gate 前，macOS、Windows 开发继续使用 Korvo-2 参考设备；不得以首板、结构或云台延期为由阻塞软件 V0。
- 自研板通过切换 Gate 后成为主要设备，Korvo-2 保留为参考、差异回归和故障回退。
- 待机必须关闭摄像头和跟随；端侧视觉不得上传或保存原始帧，物理遮挡和运动急停优先于软件请求。

## 7. 测试要求

按任务风险选择验证：

- Schema 和权限：单元测试。
- Bridge 与适配器：集成测试、版本矩阵和故障注入。
- Web 流程：浏览器自动化和关键视口检查。
- 语音链路：真实设备或录音回放、延迟分位数据。
- 消息发送：专用测试账号、重复请求、联系人歧义和断网测试。
- 更新与卸载：全新环境、升级、失败回滚和残留检查。
- 陪伴策略：固定场景集、人工评分和安全红队。
- 自研硬件：板级 Bring-up、双轴轨迹/限位、摄像头隐私、声学干扰、8 小时稳定和双平台刷机/诊断交接。

不得用 Mock 成功替代真实本地应用集成验收。

## 8. Git 和交付

- 当前项目成为独立仓库前，不得把文件提交到上级仓库。
- 创建分支默认使用 `codex/` 前缀，除非用户指定其他名称。
- 未经授权不创建提交、不推送、不创建 PR。
- 暂存前列出准确文件范围。
- 不使用 `git reset --hard`、`git checkout --` 或清理用户改动。
- 提交、推送、部署和生产验收分别提供直接证据。

## 10. 停止条件

遇到以下情况停止并请求决策：

- 产品规则冲突。
- 需要扩大本地权限或数据范围。
- 需要发送真实外部消息或操作真实账号。
- 目标应用不提供稳定接口，继续实现只能依赖高风险盲操作。
- 需要新增付费服务、商业授权或硬件采购。
- 任务要求会覆盖用户现有修改。
- 验收标准无法从现有资料确定。
