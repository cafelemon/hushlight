# Hushlight Web W0 产品需求

> 上游产品基线：`../../docs/01_prd.md`  
> 本文只细化 W0，不修改根目录 PRD 的产品规则。

## 1. 用户目标

用户打开 Web 后，应能快速知道小熙、电脑连接和关键权限是否可用，并能找到角色、陪伴模式、记忆与活动记录的管理入口。

## 2. W0 用户故事

| ID | 用户故事 | W0 验收 |
| --- | --- | --- |
| WEB-W0-001 | 用户能理解当前整体状态 | 总览同时显示设备、Bridge、权限和最近活动摘要 |
| WEB-W0-002 | 用户能找到设备管理入口 | 设备页显示绑定入口与“尚未接入”事实 |
| WEB-W0-003 | 用户能预览陪伴设置 | 模式与主动关怀设置可本地切换，并注明未同步 |
| WEB-W0-004 | 用户能理解 Bridge 的作用 | 页面不出现端口、令牌、MCP 或命令行 |
| WEB-W0-005 | 用户能按能力理解权限 | 音乐、音量、提醒、打开内容和消息分别展示 |
| WEB-W0-006 | 用户能管理记忆入口 | 提供查看、编辑、删除的界面骨架和空状态 |
| WEB-W0-007 | 用户能追踪动作结果 | 活动页区分成功、失败、阻止和待确认 |
| WEB-W0-008 | 用户能在小屏幕完成导航 | 390px 宽度无横向滚动，主要入口可达 |

## 3. 信息架构

```text
总览
├── 连接摘要
├── 下一步建议
└── 最近活动
设备
陪伴设置
Bridge 与权限
记忆
活动记录
```

## 4. 可见状态规则

- 页面顶部持续展示数据来源；W0 固定为“本地预览”。
- 未接入云端时，设备与 Bridge 使用“尚未连接/未安装”，不得显示伪在线。
- 动作成功必须来自未来 API 的执行结果；W0 仅展示明确标注的说明性示例。
- 危险或外部动作不得在 W0 提供可执行按钮。
- 删除记忆需要二次确认；W0 只验证界面，不产生云端删除。

## 5. 非功能要求

- 支持当前主流现代浏览器；生产构建不依赖运行时 CDN。
- 键盘焦点可见，按钮有可访问名称，状态不只依赖颜色表达。
- 主要内容宽度稳定，桌面端适合重复扫描，移动端改为单列。
- 数据访问必须通过 Repository 接口，页面不直接读取散落 Mock 常量。
