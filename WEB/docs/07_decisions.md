# Hushlight Web 决策记录

## WEB-D-001 使用模块化单体 SPA

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | W0 使用 React + TypeScript + Vite，按 App/Pages/Features/Domain/Data/UI 分层 |
| 原因 | 适合控制台演进；保持部署简单；无需提前引入微前端或 SSR |
| 影响 | 若未来出现公开营销站或 SEO 需求，另行评估，不与控制台混为同一渲染目标 |

## WEB-D-002 W0 使用可替换的本地预览数据源

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | 页面依赖 Repository 接口；内存实现必须返回 `source: preview` |
| 原因 | 云端协议未冻结，但可以先验证信息架构、状态和响应式体验 |
| 影响 | W0 不能作为真实设备或 Bridge 联调证据；W1 以 HTTP 实现替换数据层 |

## WEB-D-003 暂不引入大型 UI 和数据框架

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-13 |
| 决策 | W0 使用原生 CSS Token；TanStack Query 延迟至 W1 |
| 原因 | 当前重点是稳定骨架与产品语义，避免在 API 和组件规模未明确时增加约束 |
| 影响 | W1 接入真实 API 时复核缓存、表单、组件库和可访问性成本 |

## WEB-D-004 固定四视口浏览器门禁

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-14 |
| 决策 | 使用 Playwright 1.61.1 固化 1280×720、1440×900、1920×1080、390×844 的路由、交互、控制台和溢出测试；正式证据另运行 axe、请求隔离和非空像素检查 |
| 原因 | 一次性浏览器检查不能作为持续回归证据；W1 接口接入前需要稳定页面行为基线 |
| 影响 | 新页面和关键交互必须进入 `tests/e2e` 与 `tests/ui-evidence.config.json`；测试通过仍不代表实机或 Bridge 验收 |
